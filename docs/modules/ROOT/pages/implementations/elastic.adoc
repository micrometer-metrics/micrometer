== Configuring

The following example configures an Elasticsearch instance:

[source,java]
----
ElasticConfig elasticConfig = new ElasticConfig() {
    @Override
    public @Nullable String get(String k) {
        return null;
    }
};
MeterRegistry registry = new ElasticMeterRegistry(elasticConfig, Clock.SYSTEM);
----

`ElasticConfig` is an interface with a set of default methods. If, in the implementation of `get(String k)`, rather than returning `null`, you instead bind it to a property source, you can override the default configuration. For example, Micrometer's Spring Boot support binds properties that are prefixed with `management.metrics.export.elastic` directly to the `ElasticConfig`:

[source,yml]
----
management.metrics.export.elastic:
    # You will probably want disable Elastic publishing in a local development profile.
    enabled: true

    # The interval at which metrics are sent to Elastic. The default is 1 minute.
    step: 1m

    # The index to store metrics in, defaults to "micrometer-metrics"
    index: micrometer-metrics
----

== Index Retention

The registry writes the metrics to date-based indices, named after the `index`, the `indexDateSeparator` and the `indexDateFormat` (for instance, `micrometer-metrics-2026-10` with the defaults, so a new index every month).
Micrometer does not delete old indices: the retention of the metrics is left to the Elasticsearch side, where it is usually managed centrally for all the applications that share the indices.
Without cleanup, the number of indices (and shards) keeps growing until it reaches the limits of the cluster.

For example, an https://www.elastic.co/guide/en/elasticsearch/reference/current/index-lifecycle-management.html[index lifecycle management (ILM)] policy with a delete phase can delete the indices once they reach a given age.
As the registry writes to the dated indices directly rather than through a rollover alias, such a policy should not use the rollover action.
The policy can be applied to the metrics indices through the `index.lifecycle.name` setting of an index template that matches them.
When `autoCreateIndex` is enabled, the registry creates an index template named `metrics_template` for the `<index>*` pattern only if it does not exist yet, so you can create that template yourself (with the same mappings and the lifecycle setting) or disable `autoCreateIndex` and manage the template on the Elasticsearch side.

== Elastic APM agent integration

If you are using the Elastic APM agent, it can automatically collect metrics from Micrometer `MeterRegistry` instances. If you want only metrics collected by the Elastic APM agent and not shipped anywhere else, you can use the `SimpleMeterRegistry`. See the https://www.elastic.co/guide/en/apm/agent/java/current/metrics.html#metrics-micrometer[Elastic docs] for more details.
