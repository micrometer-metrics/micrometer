= Micrometer Logging Registry
:sectnums:
:system: logging

`LoggingMeterRegistry` is a `MeterRegistry` that publishes metrics to a logger (or to another `Consumer<String>`). It is useful for inspecting metrics locally without a metrics backend (in production, use a real metrics backend instead). `LoggingMeterRegistry` is included in `micrometer-core`, so no additional dependencies are needed.

== Setup

By default, the registry logs through the `io.micrometer.core.instrument.logging.LoggingMeterRegistry` logger once per minute on `INFO` level.

== Configuration

Use `LoggingRegistryConfig` to configure the publish interval and/or whether meters that have no activity in an interval should still be logged.

-----

-----

`LoggingRegistryConfig` is an interface with a set of default methods. If, in the implementation of `get(String k)`, rather than returning `null`, you instead bind it to a property source (for example, a simple `Map` can work), you can override the default configuration through properties:

[source,java,subs=+attributes]
----
include::{include-java}/metrics/LoggingMeterRegistryTests.java[tags=properties_config,indent=0]
----

The supported properties are `logging.step`, `logging.logInactive`, and `logging.enabled` (set it to `false` to stop publishing).

NOTE: By default, meters that had no activity in the publishing interval are omitted (a time gauge counts as inactive when it reports 0). Gauges and custom meters are always published.
